### 本轮概念与问答总结

- **点是否能缩放？** 点无大小，缩放改变的是相对缩放中心的位移，从而改变顶点间距离。
- **顶点与矩阵谁在左？** `System.Numerics` 使用行向量约定，数学上为 `p × M × V × P`。列向量约定也合法，但需配套转置矩阵并反转组合顺序；不能直接交换同一矩阵与向量的位置。向量约定和矩阵内存布局是不同问题。
- **为什么位置用四维且 w=1？** 齐次表示让平移可由矩阵表达；投影输出的 w 必须保留，不能当作普通三维屏幕坐标。
- **NDC 怎样得到？** 裁剪后令 `ndc = (clip.x/clip.w, clip.y/clip.w, clip.z/clip.w)`；不是调用向量 `Normalize`。
- **NDC 为什么有 z？** x、y 决定画面位置，z 保留深度用于遮挡判断。当前投影约定可见 NDC 的 x、y 在 [-1,1]，z 在 [0,1]，越小越近。透视投影下 z 与观察空间距离通常非线性，不用 NDC 计算普通世界距离或光照。
- **是否继续用原来的 DrawTriangle？** 是。它仍接收屏幕空间顶点；新增的模型绘制流程只是为它准备输入。
- **透视正确插值解决什么？** 位置的透视投影已使近处三角形区域更大、远处更小；但一个三角形本身仍可能跨越很大的近远深度。直接按屏幕重心坐标插值 UV 会把纹理均匀分给屏幕区域。保存 `1/W` 并对 `UV/W`、`1/W` 插值后相除，才会让纹理在三维表面上均匀、在屏幕上呈现近大远小。
- RTR4 阅读仍为第 2、3 章完成首次阅读，第 2 章第二轮复习推进至 2.5；本轮是软件渲染实践，没有推进新的阅读章节。

## 涉及知识

### MipMap：预过滤纹理层级与手动选层（2026-09-19）

**MIP** 来自拉丁语 *multum in parvo*，意为“以小寓大”（many things in a small place）。MipMap 不是另一张独立纹理，而是同一纹理的一串预计算低分辨率版本：

```text
Level 0: 原图，例如 1024×1024
Level 1:          512×512
Level 2:          256×256
...
最后一层:           1×1
```

双线性过滤只在同一层的四个相邻纹素之间平滑；远处或倾斜表面上，一个屏幕像素可能覆盖很多原图纹素，仍会产生闪烁和摩尔纹。MipMap 让采样器从更小、已平均过的层级取样：近处通常用 level 0，远处使用较大的 level。完整 Mip 链的存储量约为原图的 `1 + 1/4 + 1/16 + ... = 4/3`，即额外约 33%。

当前职责划分：`MipLevel` 只保存一层的 `Width`、`Height` 与 `Pixels`；`Texture` 保存所有层、生成链并处理各层采样；`Rasterizer` 当前只传入调试用的固定层级，下一节才计算自动 LOD。

#### 为什么生成下一层时要传入 `x * 2, y * 2`？

每下降一级，目标层的一个纹素代表源层约 `2×2` 个纹素。目标 `(x, y)` 对应的源层左上角是 `(2x, 2y)`：

```text
源层 x:    0 1 2 3 4 5 6 7
目标层 x:  0   1   2   3

目标 0 → 源 0、1
目标 1 → 源 2、3
目标 2 → 源 4、5
目标 3 → 源 6、7
```

因此 `Average2X2(source, x * 2, y * 2)` 平均 `(2x, 2y)`、`(2x+1, 2y)`、`(2x, 2y+1)`、`(2x+1, 2y+1)`。若只传 `(x, y)`，相邻目标像素会重叠读取源像素，且源图右下区域可能不参与下采样。

#### 为什么尺寸写作 `(source.Width + 1) / 2`？

C# 整数除法向下取整。偶数宽度时两种写法相同：`4 / 2 = 2`。奇数宽度若直接写 `5 / 2 = 2`，简单的两个 `2×2` 区域只覆盖源纹素 `0..3`：

```text
源：   [0] [1] [2] [3] [4]
目标： [0]     [1]
覆盖： 0,1     2,3       （4 未被简单 2×2 平均覆盖）
```

当前教学实现采用向上取半：`(5 + 1) / 2 = 3`。最后一个目标纹素覆盖源 `4` 与 Clamp 后重复的边缘 `4`：

```text
源：   [0] [1] [2] [3] [4]
目标： [0]     [1]     [2]
覆盖： 0,1     2,3     4,边缘重复
```

这是不会直接遗漏边缘、容易实现的简化方案。常见 GPU 对非 2 的幂纹理通常向下取半，并使用更精确的重采样覆盖源图；对本次常见的 2 的幂尺寸纹理，两种策略没有差异。

#### 当前接口与下一节

```csharp
Color SampleBilinear(Vector2 uv, int mipmapLevel)
```

当前由调用者指定整数层级，只用于验证。下一节不再固定传入 `3`：要从相邻屏幕像素的透视正确 UV 求 `dUV/dx`、`dUV/dy`，估计像素覆盖的纹素范围，并得到小数 `lod`。随后在相邻两层之间混合，即三线性过滤。

### UV、纹理采样与当前插值方式（2026-09-14）

**纹理图**保存的是颜色像素；**UV** 保存的是模型表面应到纹理图何处取色的二维坐标。UV 通常位于 `[0, 1] × [0, 1]`，但其意义由寻址方式决定。当前 `SampleNearest` 使用 Clamp，因此超出范围的坐标会固定在纹理边缘。

当前数据流为：

```text
duck.fbx 的 UV0
→ Assimp.TextureCoordinateChannels[0]
→ Vertex.UV
→ ClipVertex.UV
→ 裁剪产生的新顶点以同一 t 插值 UV
→ 屏幕 Vertex.UV 与 Vertex.InvW (= 1 / ClipVertex.Pos.W)
→ 重心坐标插值 UV/W 与 1/W，并相除得到像素 UV
→ Texture.SampleNearest(uv)
→ FrameBuffer 像素颜色
```

- 位置会经过 `MVP` 变换；UV 不参与模型、观察或投影变换，只作为顶点属性随顶点流动。
- `ToScreenVertex` 在完成位置的透视除法时，额外保存 `InvW = 1 / clip.W`。`InvW` 不是 NDC 深度，也不是深度缓冲值；它只用于修正顶点属性的插值。
- 光栅化时令 `λ0、λ1、λ2` 为当前像素相对于屏幕三角形的重心坐标。曾使用的屏幕空间线性（仿射）插值为：

```text
UV_linear = λ0 UV0 + λ1 UV1 + λ2 UV2
```

- 仿射插值把 UV 在投影后的屏幕三角形中均匀分配；当一个三角形自身跨越很大的近远深度时，远端被投影压缩这一事实没有反映到 UV 分配中，纹理格会错误地趋于屏幕空间均匀。
- 当前使用透视正确插值（perspective-correct interpolation）：

```text
UV_perspective =
  [λ0 (UV0 / W0) + λ1 (UV1 / W1) + λ2 (UV2 / W2)]
  / [λ0 (1 / W0) + λ1 (1 / W1) + λ2 (1 / W2)]
```

实现时先计算 `invW = λ0/W0 + λ1/W1 + λ2/W2`，分子为 `λ0 UV0/W0 + λ1 UV1/W1 + λ2 UV2/W2`，最后以分子除以 `invW`。这等价于先以 `1/W` 修正屏幕重心权重、归一化后再组合 UV；因而远端纹理格更密，近端纹理格更大。

裁剪阶段不需要为此改写：它仍应在裁剪空间对位置和原始 UV 按同一 `t` 插值。透视正确处理发生在裁剪完成、屏幕三角形光栅化时。GPU 对普通 UV 插值通常默认做同类校正；显式指定 `noperspective` 才会得到屏幕空间线性插值。

### 双线性过滤（2026-09-19）

`SampleNearest` 会将连续纹素坐标直接取整，因此采样位置跨过最近纹素的分界线时，颜色会突然跳变。`SampleBilinear` 保留连续坐标的小数部分，并混合周围四个纹素，使颜色随 UV 连续变化。

当前先沿用 `SampleNearest` 的 UV Clamp 与 V 翻转，再计算：

```text
x = u × (Width - 1)
y = v × (Height - 1)
x0 = floor(x), y0 = floor(y)
x1 = x0 + 1, y1 = y0 + 1
dx0 = x - x0, dx1 = x1 - x
dy0 = y - y0, dy1 = y1 - y
```

翻转 V 后使用图像坐标：`y` 越小越靠上。因此四个颜色及其权重为：

```text
左上 c00(x0, y0)：dx1 × dy1
右上 c10(x1, y0)：dx0 × dy1
左下 c01(x0, y1)：dx1 × dy0
右下 c11(x1, y1)：dx0 × dy0
```

权重来自两次一维线性插值，而不是额外规定的规则。先沿每一行横向插值：

```text
top    = c00 × dx1 + c10 × dx0
bottom = c01 × dx1 + c11 × dx0
```

再沿纵向插值：

```text
result = top × dy1 + bottom × dy0
```

将前两式代入并展开，即得到：

```text
result = c00 × dx1 × dy1
       + c10 × dx0 × dy1
       + c01 × dx1 × dy0
       + c11 × dx0 × dy0
```

每个角的权重等于它所在列的横向影响与所在行的纵向影响之积。由于 `dx0 + dx1 = 1`、`dy0 + dy1 = 1`，四个权重之和为 `(dx0 + dx1) × (dy0 + dy1) = 1`，所以结果是颜色的加权平均。对 R、G、B、A 分别作加权和后，结果必须以 `byte` 通道构造 `Color`。直接将 `0–255` 范围的插值结果传给浮点 `Color` 构造函数，会被当作 `0–1` 的归一化颜色，导致高亮通道饱和、橙色等细节错误地趋向纯黄。

在边缘处，`x1/y1` 仍保留为用于计算权重的理论相邻坐标；仅在访问数组时将右、下邻居 Clamp 到最后一列、最后一行。这等价于将边缘纹素向纹理外无限延伸，符合当前 Clamp 寻址约定。与最近邻对比时，双线性结果应更平滑，同时仍保留鸭嘴和阴影等颜色差异。

### Repeat 纹理寻址（2026-09-19，已完成）

Repeat（也称 Wrap）是纹理寻址模式，不复制纹理像素；它只将每次采样得到的任意 UV 坐标映射回同一张纹理的一个周期。对每个分量分别计算：

```text
repeat(t) = t - floor(t)
```

结果始终位于 `[0, 1)`，并且正确处理负坐标：`repeat(2.3) = 0.3`、`repeat(-0.2) = 0.8`。不能直接使用 C# 的 `%`，因为 `-0.2f % 1f` 仍为 `-0.2f`。

当前 `SampleBilinear` 使用此规则处理输入 UV，然后沿用 V 翻转与双线性过滤。右、下邻居的数组下标使用 `% Width`、`% Height` 回到第 0 列/行，以匹配 Repeat 的边缘寻址。`Rasterizer` 当前调用该采样路径。

验证时，程序生成黑白棋盘格纹理，并提交一个正对相机的矩形。该矩形两组三角形的顶点 UV 覆盖 `(0, 0)` 到 `(4, 4)`：光栅化会为每个像素插值出连续 UV，`u/v` 每跨过一个整数就经 Repeat 回到同一张棋盘纹理的起点，因此横纵方向各经历四个纹理周期。没有预先复制四张纹理。

鸭子专用贴图不适合此验证：它是为鸭子各 UV 岛唯一展开的纹理，放大其 UV 会将眼睛、翅膀等内容循环采样到错误的模型部位。可 Repeat 的纹理应确保左右边缘、上下边缘可无缝衔接；砖墙、地面、棋盘格、噪声等是典型用途。

### 像素中心采样

光栅化时，屏幕并不是连续平面，而是由一个个像素格组成。判断三角形是否覆盖某个像素时，先采用一个简单且稳定的规则：**若该像素的中心位于三角形内，就填充该像素。**

- 本项目采用“整数坐标表示像素左上角”的约定：像素 `(x, y)` 覆盖 `[x, x + 1] × [y, y + 1]`，其中心为 `(x + 0.5, y + 0.5)`。
- 因此遍历帧缓冲索引 `x`、`y` 时，用 `IsInTriangle(x + 0.5f, y + 0.5f, triangle)` 判断；确认覆盖后，仍用整数索引 `SetPixel(x, y, color)` 写入。
- 前者是**几何采样坐标**：`(x + 0.5, y + 0.5)` 代表第 `(x, y)` 个像素格的中心，用来回答“这个像素应不应该被三角形覆盖？”；后者是**存储索引**：`SetPixel(x, y, color)` 把颜色写入 `pixels[y * width + x]` 中对应的那个格子。两者指向同一个像素，只是一个用于几何判断、一个用于数组寻址。
- 另一种也合理的约定是“整数坐标表示像素中心”，此时像素范围为 `[x - 0.5, x + 0.5]`，判断时直接使用 `(x, y)`。两套约定不能混用，否则图形会出现半像素偏移。
- `+0.5` 不是对屏幕坐标的额外移动，而是从像素格左上角移动到同一个像素格的中心。

### Bresenham 画线算法

目标是在离散像素网格上，用尽量少的计算逼近两个端点之间的直线。它适用于“每一步都要决定下一个像素该向哪个格子走”的场景。

- 对斜率位于 `0 ≤ m ≤ 1` 的线段，主方向是 `x`：每一步 `x` 加一，而 `y` 只在需要时加一。
- 用一个**整数误差项**表示当前像素中心相对理想直线的位置；误差跨过阈值时，选择对角方向的下一个像素，并更新误差。
- 它避免了浮点计算，时间复杂度为 `O(max(|Δx|, |Δy|))`，空间复杂度为 `O(1)`。
- 完整实现要处理所有象限与陡线：当 `|Δy| > |Δx|` 时交换主方向；根据端点相对位置选择 `x`、`y` 的递增或递减方向。
- 它绘制的是线段的离散近似，不是三角形光栅化本身；但两者都体现了“连续几何如何覆盖离散像素”的问题。

### 重心坐标与顶点颜色插值（2026-09-08）

已在 `Rasterizer.DrawTriangle` 中完成。对像素中心 `P = (x + 0.5, y + 0.5)`，先计算三角形的有符号双倍面积：

```text
D = E(V0, V1, V2)
```

若 `|D|` 接近零，三角形退化，直接跳过。否则重心坐标为：

```text
λ0 = E(V1, V2, P) / D
λ1 = E(V2, V0, P) / D
λ2 = E(V0, V1, P) / D
```

- `λ0、λ1、λ2` 同时非负时，P 位于三角形内部或边界；由于分子、分母共享同一符号约定，这一判断同时支持顺时针与逆时针顶点顺序。
- 同一组权重既用于覆盖测试，也用于插值顶点属性。当前按通道插值颜色：`C(P) = λ0 C0 + λ1 C1 + λ2 C2`，得到渐变三角形。
- `Raylib_cs.Color` 构造函数参数顺序为 `R, G, B, A`；插值时误写为 `R, B, G, A` 会使绿色与蓝色通道交换。
- 这段颜色插值的重心坐标仍是屏幕空间权重；当前 UV 已额外使用 `1/W` 修正为透视正确插值。颜色、世界坐标等其他随表面变化的属性也可按同一思路处理。

## 问答记录

### Q1：重心坐标的公式是什么？

对三角形顶点 A、B、C 和采样点 P，重心坐标是三个权重 λA、λB、λC，满足：

```text
P = λA A + λB B + λC C
λA + λB + λC = 1
```

定义二维边函数（有符号面积的两倍）：

```text
E(U, V, P) = (V.x - U.x)(P.y - U.y) - (V.y - U.y)(P.x - U.x)
D = E(A, B, C)
λA = E(B, C, P) / D
λB = E(C, A, P) / D
λC = E(A, B, P) / D
```

每个权重是“采样点与该顶点对边构成的小三角形”的有符号面积除以整个三角形的有符号面积。分子、分母必须采用一致的边函数符号约定；不要只对分母取绝对值。D 为零说明三角形退化，不能进行除法。

在三角形内部，三个权重均非负；位于顶点 A 时权重为 (1, 0, 0)，位于 BC 边时 λA = 0，重心处为 (1/3, 1/3, 1/3)。公共边的像素归属还需要单独的覆盖规则。

当前屏幕空间光栅化中，取 P = (x + 0.5, y + 0.5)，用这些权重对各颜色通道插值：

```text
color(P) = λA colorA + λB colorB + λC colorC
```

示例：A=(0,0)、B=(4,0)、C=(0,4)、P=(1,1)，得到 D=16，三个分子为 8、4、4，因此权重为 (0.5, 0.25, 0.25)。

这里得到的是屏幕空间重心权重；在透视投影下，UV 等属性需再结合每个顶点的 `1/W` 得到透视正确插值。

### Q2：边函数是什么？

边函数用一个带符号的数，判断点 P 位于有向边 A→B 的哪一侧。定义：

```text
E(A, B, P) = (B.x - A.x)(P.y - A.y) - (B.y - A.y)(P.x - A.x)
```

它是向量 AB 与 AP 的二维叉积标量，也是三角形 ABP 有符号面积的两倍。E=0 表示 P 在边所在的直线上（不保证在线段内）；正负表示直线的两侧。在 x 向右、y 向上的坐标系中，正值表示左侧、负值表示右侧；屏幕 y 向下时，视觉上的左右关系反转。

例如 A=(0,0)、B=(4,0)，则 E(A,B,P)=4P.y；P=(1,1) 得到 4，P=(1,-1) 得到 -4，P=(1,0) 得到 0。

对三角形，计算 E(A,B,P)、E(B,C,P)、E(C,A,P)。非退化三角形中，三个值全部非负或全部非正，说明点位于三角形内部或边界；符号混杂说明在外部。实际相邻三角形共边还需 top-left 等规则分配边界，避免重复覆盖。

边函数用于覆盖判断时只需看符号；用于重心坐标时，再除以整个三角形对应的有符号双倍面积，得到插值权重。当前项目用 P=(x+0.5,y+0.5) 作为采样点。

### Q3：非退化三角形是什么？

非退化三角形就是面积不为零的正常三角形：三个顶点不在同一条直线上。退化三角形面积为零，可能是三个不同顶点共线，也可能是两个或三个顶点重合，形状塌缩成线段或点。

用边函数判断：D = E(A,B,C)。D≠0 表示非退化，D=0 表示退化。例如 A=(0,0)、B=(4,0)、C=(2,0) 共线，D=0；把 C 改为 (2,3)，D=12，面积为 |D|/2=6。

重心坐标公式需要除以 D，因此退化三角形必须跳过。实际使用浮点数时，可根据坐标尺度设置合理的接近零判断阈值；面积很小但不为零的三角形在数学上仍然非退化。

### Q4：为什么像素采样坐标要分别对 x、y 加 0.5？

当前约定中，整数 `(x, y)` 是像素格左上角，也是帧缓冲和深度缓冲的数组索引。像素格覆盖 `[x, x + 1] × [y, y + 1]`，所以其中心为 `(x + 0.5, y + 0.5)`。光栅化用中心点进行边函数和重心坐标计算，判断这个像素是否被三角形覆盖；写入颜色或深度时仍使用整数索引 `(x, y)`。

屏幕坐标以左上角为原点：`x` 增大向右，`y` 增大向下。这与常见数学坐标系的 y 轴方向相反。
