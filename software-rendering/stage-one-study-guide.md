# 阶段一源码学习指南

这份指南对应当前可运行的 C# 软件渲染器。默认场景是 `Assets/Models/duck.fbx` 与 `Assets/Textures/duckCM.png`。现在已准备好阶段一的代码示例、实验开关和对比图片。源码是学习材料，能运行不等于已经掌握；每次只做一个实验，先预测，再观察，最后找到产生结果的代码。

## 启动与控制

在仓库根目录运行：

```powershell
dotnet run --project software-rendering/SoftwareRendering.csproj
```

在 Rider 中使用这个项目的 .NET 运行配置。项目保留 `UseAppHost=false`，通过 dotnet 宿主启动。不要使用输出目录里以前遗留的 EXE。

| 按键 | 用途 |
|---|---|
| `1 / 2 / 3` | Lambert / Phong / Blinn-Phong |
| `L` | 光照开关；关闭后直接显示纹理颜色 |
| `← / →` | 改变方向光方向 |
| `W / S` | 模型沿世界 Z 前后移动；W 远离当前相机 |
| `A / D` | yaw；`Q / E` 为 pitch；`Z / C` 为 roll |
| `N` | 法线贴图开关；初始关闭 |
| `B` | 非均匀缩放开关 |
| `M` | 正确逆转置 / 故意错误的普通模型矩阵法线变换 |
| `U` | 配套纹理 / 白色纹理；白色便于观察纯光照 |
| `P` | 鸭子 / 倾斜条纹平面；切换时重置旋转和前后位置 |
| `F` | 三线性 / 各向异性近似过滤 |
| `T` | Euler → QuaternionLocal → QuaternionWorld → Euler |
| `G` | 设置欧拉角 pitch=90° 的万向锁实验姿态 |
| `R` | 用四元数 Slerp 在一秒内回到初始朝向 |

| `H` | 隐藏或显示帮助，便于看完整画面 |

光追场景是缓存的 320×240 图片；显示时放大到窗口。它不响应鸭子场景的旋转、光照和纹理按键，FPS 也不代表光追实时性能。

## 阅读路线

1. `Vertex.cs`、`ClipVertex.cs`：一个顶点有哪些属性，各空间分别存什么。
2. `Program.DrawModel`：模型输入如何变成屏幕三角形。
3. `Rasterizer.DrawTriangle`：如何确定覆盖、深度和属性插值。
4. `Lighting.Shade`：从法线、光源方向和观察方向得到颜色。
5. `Lighting.ApplyNormalMap`：切线空间法线怎样变成世界空间法线。
6. `Texture.SampleFiltered`：一个像素覆盖的纹理足迹怎样影响采样。
7. `RotationStudy`：欧拉角、局部轴/世界轴四元数和 Slerp。
8. `RayTracingStudy`：射线找最近交点与阴影射线。
9. `StageOneVerification`：可重复验证这些关系的具体数值案例。

当前 `Vertex` 仍兼任模型输入和屏幕顶点，字段注释说明空间区别。`ModelVertex`、`ScreenVertex` 和 `Render` 是此前预留的重构骨架，不属于当前活动路径。

## 实验一 从顶点到像素

完整路径：

```text
模型位置 → Model → 世界位置 → View → 观察位置
→ Projection → 四维裁剪位置 → 六平面裁剪
→ xyz/w → NDC → 视口变换 → 屏幕坐标
```

本项目使用行向量：`p_clip = p_local × Model × View × Projection`。相机在世界 `(0,0,-3)` 朝世界 `+Z` 看；`CreateLookAt` 的观察空间前方是 `-Z`。世界原点在观察空间为 `(0,0,-3)`。

`Program.DrawModel` 保留了第一个网格第一个顶点的观察代码。在 `GC.KeepAlive(ndcX)` 行设置断点，可以查看 `viewPos.Z`、`clipPos.W`、`ndcX`。原来的固定行号会随代码新增而改变，请按表达式搜索。

当前透视矩阵满足 `clip.W = -view.Z`。保持横向位置与 FOV 不变，前方深度从 3 变成 6 时，W 从 3 变成 6，NDC X 缩小为一半。矩阵先准备分子和分母，随后独立执行除法。

为什么保留 W：右边界在 NDC 中是 `x/w ≤ 1`，在正 W 时等价为 `x ≤ w`。裁剪直接在四维中判断，不先除法。跨越近裁剪面或相机附近时，先切去不可见部分，避免除以接近零或负的 W。六个面分别为 `x+w≥0`、`w-x≥0`、`y+w≥0`、`w-y≥0`、`z≥0`、`w-z≥0`。

边跨过平面时，`t=dA/(dA-dB)` 得到交点比例；位置、UV、法线、切线和世界位置使用同一个 t 插值。留下的多边形再扇形三角化。

NDC Z 在 `[0,1]`，越小越近。它是非线性的深度值；世界空间位置另外保留，用于计算高光，不从 NDC 直接估算物体间距离。

**检查自己：** 同一个顶点远离时，哪些量改变？哪些量保持不变？为什么 `clip.Z` 与 `clip.W` 不是同一个用途？

## 实验二 Lambert 漫反射

按 `1`，先按 `L` 对比原贴图与光照，再用左右键改变光源方向。

`N` 表示单位表面法线，`L` 表示从表面指向光源的单位方向。注意这里的 L 不是光传播的方向。

```text
diffuse = max(0, dot(N,L))
brightness = ambient + diffuseStrength × diffuse
RGB = albedoRGB × brightness
```

归一化后点乘等于夹角的 cos。正对光源时是 1，侧对时是 0，背对时为负并被截到 0。常量环境项让背光面仍能看清；它不是全局光照，也没有判断被别的物体挡住的阴影。

鸭子的眼睛是贴图里的颜色。关闭光照后仍有颜色差异；关闭光照不关闭深度测试或背面剔除。导入 FBX 用 `FlipWindingOrder` 对齐当前屏幕顺时针正面的规则。

**检查自己：** 为什么只平移模型不会改变方向光的漫反射？点光源会一样吗？

## 实验三 Phong 与 Blinn-Phong

按 `2`、`3` 对比，旋转鸭子观察头部和身体的白色高光。高光是另加的白色镜面项，不直接乘纹理颜色。

`V = normalize(cameraPosition - worldPosition)`，表示从当前表面点指向相机。每个像素的世界位置是透视正确插值得到的。

```text
Phong:
R = reflect(-L,N)
specular = max(0, dot(R,V)) ^ PhongExponent

Blinn-Phong:
H = normalize(L+V)
specular = max(0, dot(N,H)) ^ BlinnExponent

RGB = albedoRGB × (ambient + kd × diffuse) + white × ks × specular
```

Phong 比较反射方向与观察方向；Blinn-Phong 比较法线与半程向量。指数越大，高光通常越窄。相同指数不代表相同高光宽度，示例选择 24 与 96 作近似对比；“四倍”不是所有角度都严格成立的换算。

光源在背面时禁止高光。`L+V` 长度接近零时安全返回零向量，避免归一化产生 NaN。

**检查自己：** 为什么高光需要相机位置，而 Lambert 不需要？改变指数与改变光照强度分别改变什么？

## 实验四 为什么法线要用逆转置

按 `U` 显示白色纹理，按 `B` 拉伸模型，再反复按 `M` 比较。默认 M 为正确的逆转置；关闭后是故意错误的算法。拉伸后如果超出画面，用 W 让模型远一些。

表面切线沿模型矩阵的线性部分 A 变换。法线必须仍与变换后的切线垂直，所以行向量写法为：

```text
t' = t × A
n' = normalize(n × inverse(A)^T)
```

如果直接把法线乘 A，非均匀缩放会让法线倾斜到错误的方向。纯旋转时逆转置与原旋转矩阵相同；平移对方向无作用。`Vector3.TransformNormal` 不包含平移，但仍需要传正确的逆转置矩阵，函数名不会自动帮你求逆转置。

顶点法线在变换后归一化。经过裁剪和透视正确插值后，像素法线再归一化，因为插值通常会改变长度。

**检查自己：** 为什么测试只用均匀缩放容易发现不了错误？为什么 MVP 不能拿来变换世界空间光照用的法线？

## 实验五 切线空间与法线贴图

按 `3`，再按 `N`。鸭子表面出现周期凹凸高光，但轮廓不改变。可按 U 去掉鸭子原贴图颜色，专门观察法线效果。

法线贴图由 `Texture.CreateNormalMap` 程序生成，蓝色分量为正，红绿分量表示沿 U/V 的倾斜。它没有改动原始鸭子贴图，也没有增加网格顶点。

每个表面位置有三根轴：

- T：切线，沿 UV 的 +U。
- B：副切线，沿 UV 的 +V。
- N：几何法线，垂直表面。

Assimp 导入 T/B；切线的 w 保存 `sign(dot(cross(N,T),B))`。镜像 UV 需要这个正负号。N 用逆转置变换，T 是表面切线，用普通模型矩阵变换；都不能用投影矩阵。

`Lighting.ApplyNormalMap` 中：

```text
N = normalize(interpolatedNormal)
T = normalize(interpolatedTangent - N × dot(N,interpolatedTangent))
B = cross(N,T) × handedness
normalTS = normalize(RGB × 2 - 1)
normalWorld = normalize(T × normalTS.x + B × normalTS.y + N × normalTS.z)
```

这里最后一行的乘号是“向量乘标量”；把法线在 T/B/N 三根轴上的分量相加，就完成坐标变换。Gram-Schmidt 那一步确保 T 与 N 垂直。缺少有效切线时跳过法线贴图，避免无效法线破坏渲染。

UV、法线、切线、世界位置都采用同一个透视正确权重：

```text
q = λ0/w0 + λ1/w1 + λ2/w2
attribute = (λ0 × attribute0/w0 + λ1 × attribute1/w1 + λ2 × attribute2/w2) / q
```

NDC 深度 Z 仍使用屏幕重心坐标线性插值，不再重复做此修正。

**检查自己：** 为什么法线贴图不能直接把解码后的 RGB 当成世界空间法线？为什么它改变高光却不改变鸭子轮廓？

## 实验六 各向异性过滤

按 P 切换条纹平面，它会自动关闭光照，便于比较纹理。按 F 切换过滤，观察远处条纹是否仍保留横向细节。按 P 回鸭子会恢复光照。

像素中心、右边一步、下边一步的 UV 差给出 `dUVdx/dUVdy`。乘纹理尺寸后，得到屏幕像素在纹理中覆盖的两条纹素向量。

三线性过滤用较大的向量长度选择 Mip 层。因此倾斜平面沿纵深覆盖很多纹素时，即使横向只覆盖很少纹素，横向细节也一起变模糊。

各向异性示例根据 `J × J^T` 的特征值估计足迹的长轴和短轴：短轴决定 Mip 层，长轴决定采样方向与次数，然后把多个三线性采样结果平均。默认最多 8 次。超过上限时提高 LOD，接受一些模糊，避免沿长轴漏采。

这是 CPU 上的教学近似，不是硬件实现的精确复刻，也不是完整 EWA 过滤。远处可能仍有混叠；额外采样增加计算成本。F 也控制法线贴图的过滤。

为了保持 Repeat 接缝连续，双线性采样现在使用纹素中心约定 `x=u×width-0.5`，四个邻居都 Wrap，包括负下标。

**检查自己：** “一个像素跨越 64 个纵向纹素，却只跨越 1 个横向纹素”为什么不能简单用同一低分辨率 Mip 层解决？

## 实验七 欧拉角 四元数与万向锁

先在 Euler 模式中用 A/D、Q/E、Z/C 分别旋转。示例明确固定顺序：

```text
行向量：R = Rz(roll) × Rx(pitch) × Ry(yaw)
```

旋转顺序不能交换。欧拉角是三个参数，并不意味着随时都有三个互不依赖的旋转轴。

按 G 设置 pitch=90°。这时只增加 yaw 与只减少等量 roll 可以产生同样的姿态变化；两个控制失去独立性。`StageOneVerification` 验证了这个矩阵关系。画面上的角度显示也会帮助你确认当前参数。

按 T 切入 QuaternionLocal，同样使用三个轴按键。这时输入被转成小的增量旋转，累积到一个归一化四元数中，而不是累积三组欧拉参数。再次按 T 切入 QuaternionWorld，对比已有旋转后再输入 yaw 的行为：局部轴随物体转，世界轴固定。

System.Numerics 的组合满足 `M(q1*q2)=M(q2)*M(q1)`，所以这里的局部增量使用 `orientation*delta`，世界增量使用 `delta*orientation`。不要把矩阵乘法顺序直接复制到四元数乘法。

从 Euler 切入四元数保留姿态；从 QuaternionWorld 回 Euler 会重置朝向，这是示例的显式行为，避免悄悄引入欧拉角提取。按 R 用 Slerp 平滑回到初始朝向，不是把三个欧拉角各自线性插值。归一化减少长期累积误差。

四元数可避免用欧拉参数存储姿态时的万向锁，但若仍在奇异姿态上用欧拉角定义输入，再转四元数，输入本身的轴耦合不会神奇消失。本示例的四元数模式使用局部/世界增量控制。

**检查自己：** 先绕 X 再绕 Y 与反过来一样吗？已经倾斜的模型，“绕自己的上方向”和“绕世界上方向”分别意味着什么？

## 实验八 光栅化与光追

按 K 进入独立球体光追场景，按 J 切换阴影。代码在 `RayTracingStudy`，使用同一个经验光照公式，但可见性方法改变了。

| 问题 | 当前光栅化 | 光追对照 |
|---|---|---|
| 从哪里开始 | 遍历三角形，找覆盖像素 | 从每个像素发相机射线 |
| 谁最靠近相机 | 深度缓冲保留最小 NDC Z | 保留最小正交点距离 t |
| 法线怎么得到 | 导入顶点法线并插值 | 球面上用交点减球心；地面用固定法线 |
| 物体遮住光源 | 当前未实现；可用 Shadow Map 等方法 | 从交点向光源发阴影射线 |
| 反射 | 可用环境贴图、SSR 或光追等 | 可以继续沿反射方向发射线；本示例未实现 |
| 计算成本 | 与三角形覆盖、过绘制和着色有关 | 与像素、射线数量、求交和加速结构有关 |

求交使用 `P(t)=origin+t×direction`。单位方向射线与球体求交得到一元二次方程；选择最小正根，才是前方最近表面。球内部出发时可使用较大的正根。

阴影射线从 `P+N×epsilon` 发出，避免浮点误差让它立即撞到自己。这不是完整全局光照；遮挡时仅保留环境项。地面棋盘在远处会混叠，因为这个小示例没有多重采样与纹理足迹过滤。

两种场景使用不同几何，不能据此比较画质或真实性能；这个实验用于理解求交、可见性和阴影的流程差别。

## 当前边界与阶段一验收

当前光栅化没有 PBR、物体之间的阴影、透明混合，也没有做 sRGB→线性光照→sRGB 的完整颜色流程。Phong/Blinn-Phong 是经验模型；高光被限制到 8 位 RGB。法线贴图只改变着色法线，不能替代位移和轮廓几何。渲染结果以展示阶段一原理为目的。

阶段一的示例与核心作品已经准备齐全。你可以用以下条件检查自己的理解：

- 能沿一次 DrawModel 说出各阶段输入、输出与空间。
- 能解释 W、透视除法、六平面裁剪、透视正确插值。
- 能说明深度测试与背面剔除解决的是不同问题。
- 能解释 N/L/V/R/H 的方向与 Phong/Blinn-Phong 的区别。
- 能通过非均匀缩放说明逆转置的必要性。
- 能解释 TBN、法线贴图解码和纹理足迹。
- 能用实验说明旋转顺序、局部轴/世界轴、万向锁与 Slerp。
- 能比较光栅化与光追的可见性方法和常见代价。

可以先从 `Lighting.Shade` 开始。只看这一方法，运行 1/2/3 三种模式，并把 N、L、V 当作三个箭头来理解；有疑问时再沿它依赖的数据回到光栅化和顶点变换。
